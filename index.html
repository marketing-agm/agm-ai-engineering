The team builds internal software for AGM. Current output covers reporting, dashboards, data pipelines, and workflow tools for processes where commercial software does not fit the requirement or does not fit the budget.

Operating model

|Infrastructure, method, governance
Infrastructure
Platform and code hosting
Applications run on Cloudflare. There are no servers to purchase, maintain, or patch, and hosting cost is effectively zero at current volume. Development uses Claude Code. Source code is held in GitHub with full version history, so no application depends on an individual machine.
Build method
Construction and release
Tools are built against specific AGM processes rather than purchased as general vendor software, and released in increments. Each repository carries written development standards that the AI tools follow, which holds code conventions consistent across contributors.
Access control
Authentication and audit
Internal applications sit behind Cloudflare Zero Trust, which verifies email against AGM Google Workspace accounts. No separate passwords are issued. API keys and secrets are held centrally and are not stored in source code. The Corporate Library records every document action. Restricted folders are not visible to users or to the AI assistant without an explicit grant. The Claude business plan does not train on company data by default. Admin spend limits are set per user and organization-wide.
Vendor dependency
Portability
Most of the portfolio does not call AI at runtime. Report Studio, the KPI Dashboard, and the proposal system function without it. The components that do call AI use a standard API that can be re-pointed to another provider with a code change; the scope of that change has not been tested. Data is held in storage AGM controls and can be exported. The Cloudflare platform uses standard web technology rather than a proprietary runtime.

Basis for Pro

|Constraints on the Free plan
  • Message retention. The Free plan removes messages and files after 90 days. Records of build decisions made earlier in the year are already outside that window and are not recoverable.
  • Integration count. The Free plan permits 10 app integrations. GitHub and Cloudflare account for two. Alerting for the KPI Dashboard, the work-order digest, form submissions, and deploy notifications is not accommodated within the remaining eight.
  • External participants. Slack Connect on the Free plan is limited to one external organization. Vendor and owner correspondence currently runs through email.
  • Workflow Builder. Available from Pro. Forms, approvals, routing, and scheduled posts can be built by the team that needs them rather than by the development team.
Argument against Pro. Business+ at $15.00 per seat per month is double the cost and adds SAML SSO, SCIM provisioning, data residency selection, compliance export, and a 99.99% uptime commitment. AGM currently authenticates internal applications through Cloudflare Zero Trust against Google Workspace, so single sign-on is handled outside Slack. If Slack is later designated a system of record for compliance purposes, Business+ becomes the required tier and the per-seat cost doubles.

Not addressed by Pro. Pro does not provide compliance export, data residency selection, or data loss prevention. Retention makes messages findable; it does not reduce their volume, and it does not establish which channel a given record belongs in. That is covered by the use requirements in the next section.

Basis for Business

|Capture method and retention

Granola captures audio from the laptop rather than joining a call as a participant. It therefore records in-person meetings, phone calls, and video calls without an invitation and without a join link. That is the operative requirement for owner, vendor, and contractor conversations that AGM does not schedule.

The Basic tier retains approximately 25 notes on a rolling basis, which is shorter than a single project. Business is the tier at which note history is retained, and it is the tier that exposes note content over MCP and the API, which is the path by which meeting content reaches the Corporate Library and internal tooling without re-entry.

Argument against Business. Enterprise at $35.00 per seat per month adds single sign-on and an organization-wide opt-out from model training. Business does not include that opt-out. If meeting content is judged to require that control, Enterprise is the required tier at 2.5 times the cost.

Not addressed by Business. Granola records and transcribes. It does not file, distribute, or act on the result; filing to the correct location remains manual unless an integration is configured for it. Consent to record is a policy question and is not governed by any product setting.

Granola
Recording requirement
Record every conversation. This applies in particular to any discussion touching a large project or a general business problem the company is working to solve. Staff do not attend meetings without a laptop and a running recording. The requirement exists so that expectations set by leadership and by internal teams are documented at the time they are set, and so that a decision made in March is retrievable in September. Notes are filed to the relevant project location the same day.
Slack
Channel use
Project work is conducted in the project channel rather than in direct messages or email. Decisions are written in the channel that owns them. Files are posted to the channel. Vendors, owners, and contractors are given a Slack Connect channel in place of an email thread.
Figma
Design file requirement
Interface changes begin as a Figma file and are reviewed there before code is written. Shared components are drawn from the team library rather than defined per file. Developers work from Dev Mode rather than from screenshots.
Claude
Development standards and spend limits
Each repository carries written development standards that the AI tools follow, which holds code conventions consistent regardless of contributor. Seat and API usage is tracked per user against admin spend limits set organization-wide.
AppFolio API
Data access method
On approval of the Database API, the scheduled-report-to-inbox method is closed to new work. New data requirements are met through the API. Existing CSV pipelines are migrated on a schedule rather than left running alongside the API.
All tools
Quarterly license review
Usage is pulled per seat each quarter. A seat with no activity in 30 days is reclaimed, downgraded, or reassigned. A tool with no activity from the team that requested it is cancelled at renewal. Renewals are not automatic.

Basis for the requirements

|Rationale
  • Coverage. A record with gaps cannot be used to establish what was asked for. If half the team records meetings and half does not, the record does not answer questions about the periods it does not cover.
  • Retained value. Message history, shared component libraries, and meeting records return value in proportion to how completely they are populated. A month in which the tool is not used produces no record for that month.
  • Cost review. A license renewal can be defended against a usage report. It cannot be defended against an absent one.
  • Handover. Staff joining a project inherit the recorded material rather than reconstructing it from conversation.
Cost of the requirements. A standing recording requirement changes how people speak in meetings, and some conversation will move to settings that are not recorded. A 30-day idle rule will occasionally reclaim a seat from someone on leave. Both outcomes are predictable and are handled by exception rather than by revising the requirement. Neither the recording requirement nor the review has been costed in staff time.
Policy Use of an approved tool is a requirement, not a preference. Usage is measured, reviewed quarterly, and seats without activity are reclaimed.

Basis for a recurring reload

|Availability and cost behavior
  • Availability. Products in production call the API on a schedule and on user request. A zero balance produces a user-facing error. A recurring reload removes that condition without an approval cycle.
  • Cost behavior. Charges are metered against tokens processed rather than against seats held. Measured cost for the Corporate Library research assistant is approximately $1 per month at current usage.
  • Controls. Spend limits are set per user and organization-wide. API keys are held centrally and are not stored in source code. Usage is attributable by product.
Argument against a recurring reload. It commits spend before the work that consumes it is scoped. The alternative is manual top-off, which was the prior arrangement and produced at least one service interruption. Because the reload threshold and ceiling are configurable, exposure is bounded by the ceiling rather than open-ended.

Not addressed. Credits do not cap consumption by any individual product. Attribution by product is available after the fact and is not enforced in advance. A defect that causes repeated API calls would draw down the balance until the ceiling is reached.
