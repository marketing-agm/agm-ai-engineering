Basis for the change

|Four clocks

AGM operates brokerage, commercial management, residential management, and association management at once. Each answers to a different regulator on a different clock, and the clocks do not start on the same day. A brokerage transaction file must survive a Department of Licensing audit for three years from the conclusion of the transaction. An association architectural decision runs seven years from the date the decision was made. A payroll register answers to Revenue for five years from the close of the tax period. A building’s basis records run until four years after the building is sold, which on a thirty-year hold is thirty-four years.

A folder structure cannot express four clocks at once. The proposal stops asking it to, and instead carries the retention rule and the destruction-eligible year inside the file name, where they travel with the document when it is downloaded, emailed, exported to a new system, or handed to an association on termination. A folder cannot do that. Metadata does not survive the same journey.

What changes
Purge becomes a search
An annual purge becomes a search on one token. An audit response becomes a saved filter. An owner records request becomes a copy operation rather than a redaction project. Nobody has to reconstruct from memory why a document was kept or destroyed.
Exposure closed
Defensible destruction
Records destroyed on a published schedule before any claim arose are defensible. The same records destroyed with no schedule and no log carry the appearance of spoliation. That distinction is the difference between a routine document request and an adverse inference at trial.
Scope
Structure, tags, naming
Three components, proposed together because they depend on each other. The folder tree files the document, the tag identifies what it is, and the name carries the retention consequence. Any one of the three on its own does not produce a defensible purge.
Not claimed
No measured saving
No baseline has been recorded for time spent filing, searching, or responding to records requests today, so no saving is quantified in this section. The case rests on capability the firm does not currently have and on exposure it currently carries, not on a labor figure.

The retention periods cited here are the team’s reading of Washington statute and rule, recorded against each code in the tables below. They are an interpretation and have not been reviewed by counsel. Legal sign-off on the retention schedule is a prerequisite to any automated destruction, and is listed among the open items at the end of this section.

File naming

|Eight fields
DIV-ASSET[_SUB]-DOCTYPE-YYYYMMDD-Descriptor-RETCODE-DTOKEN[-vNN].ext

A hyphen separates fields. An underscore separates sub-fields. CamelCase runs inside a sub-field. There is no fourth kind of punctuation.

FieldFormatRule
1 · DIV2 lettersBR brokerage, CM commercial, RM residential, HA association, CO corporate.
2 · ASSET3–12 A-Z0-9Permanent. Never reused and never renamed, not on a rebrand and not on a change of owner. Derived from street and number, or from the recorded association name. A sub-unit uses an underscore: BALLARD12_U204.
3 · DOCTYPE4 charactersSelected from the controlled list below. Nothing outside the list is permitted.
4 · YYYYMMDD8 digitsThe date on the document, not the scan date and not the upload date. Where the day is unknown, 01 is used and the descriptor says so.
5 · DescriptorCamelCase, ≤30Counterparty, unit, project, or period. Omitted rather than padded. Never a date and never a code.
6 · RETCODE4 charactersThe retention rule. Where two rules cover one record, the longer period governs and its code is the one used.
7 · DTOKEND + 4The destruction-eligible year, or one of three states: DOPEN, DHOLD, DPERM.
8 · vNNv + 2 digitsDrafts only. The final record carries no version, so there is exactly one unversioned file per record.
Characters
No spaces, ever
SharePoint encodes each space as %20. Also excluded: " * : < > ? / \ | # % & { } ~ and any leading or trailing space or period. File names run to 90 characters or fewer and the full URL stays under 400.
Path budget
Constraint created by four levels
Tenant, site, and library consume 150 to 200 characters before a folder is added, and four levels can consume another 120 to 150. The target is a deepest folder path under 250 characters. The longest real path is to be validated before build begins: Construction, Project Records, Substantial Completion Cert.
One record, one file
No bundling
Unrelated records are never combined into a single PDF. A bundle inherits the longest retention period inside it, which defeats the purge for everything else in the file.
Direction of travel
Never renamed to shorten retention
Extending a period is always permitted. Shortening one requires the Records Owner in writing and is entered in the destruction log. New codes are additive and inexpensive; redefining an existing code silently reinterprets every file already named with it, so the old code is retired and a new one issued instead.

The line that matters. AI identifies what a document is and when it happened. The legal consequence of those two facts is a deterministic lookup against a versioned, approved table. That boundary is what keeps the system auditable: a model error can produce a mis-filed document, but it cannot produce an indefensible destruction. Where no code in the list applies, AI is not permitted to invent one. It returns no match and routes to the Records Owner, who issues a new code.

Intake

|What the person does
  1. Drop the file into the asset folder. That single act sets the division and the asset. Nothing is typed.
  2. AI reads it and proposes three things: what the document is, the date the rule table says matters for that type, and a descriptor following the pattern for that type.
  3. One confirmation screen shows the complete proposed file name, AI-proposed parts highlighted, machine-set parts locked, with confidence shown per field.
  4. Accept or correct. One click accepts. Correcting the document type recomputes the retention code and destruction token automatically; a person never edits those directly.
  5. Below the threshold one-click accept is disabled. The upload still completes, but the file enters a review queue and its clock is marked unverified until a person confirms it.

Two operating rules. A file is named at the moment it is filed, never afterwards; a document that arrives as Scan0042.pdf and is renamed later is renamed wrong, or never. And where the retention clock has not started, on a live lease or an open transaction, the file is marked DOPEN rather than given a guessed year. DOPEN is a work queue. A monthly sweep of it is the single control that keeps the system honest.

Document tags

|Definition

A tag is a four-character code identifying what kind of record a document is. It is stored in two places at once: inside the file name, and in a SharePoint metadata column populated from that name on upload. The duplication is deliberate. The column drives views, filters, dashboards, and automation inside SharePoint. The name is what allows the record to be understood after it leaves SharePoint, whether downloaded, emailed to an owner, exported on termination of a management agreement, or migrated to a successor system. Metadata is stripped at that boundary; the file name is not.

Return beyond search

|Ten uses
  • Defensible destruction. The destruction-year token is the purge query: search the token, exclude holds, delete, log it. An annual project becomes a scheduled task.
  • Statute-of-limitations exposure. A second tag dimension, recorded in metadata only, answering how long the firm can still be sued over a record rather than when it may be deleted.
  • Litigation hold. A single tag freezes a document against every automated process, with no manual search for what to preserve.
  • Records production. An owner records request becomes this association minus the restricted tags. The statutory clock is ten days and never more than twenty-one; segregating by permission at filing time makes that a copy operation rather than a redaction project.
  • Critical-date alerting. Tag plus date drives automated reminders: lease expiry, insurance renewal, reserve study due, the resale certificate 45-day financial window, the 30-day deposit disposition deadline.
  • Open-item visibility. A DOPEN file sitting on a lease that has ended or a transaction that has closed surfaces as an exception rather than going unnoticed.
  • Audit readiness. A Department of Licensing audit may be unannounced and expects the initial package within two business days. Tagged trust records and a tagged contract log make that a saved filter.
  • Completeness reporting. The inverse query is the valuable one: which tags are missing. No completion certificate on a finished capital project, no move-in checklist on a tenancy holding a deposit. That is a portfolio risk report the firm cannot produce today in any form.
  • Retrieval quality. The Library research assistant answers materially better when it can scope to a record type rather than search everything. A question about CAM methodology should read reconciliation files, not every PDF on the site.
  • Turnover manifests. On termination of a management agreement, the manifest of every record class, count, and date range is generated from the tags rather than assembled by hand, inside the five business days allowed for electronic records.

The limitations tag, a second and optional dimension

The retention code answers one question: when is the firm permitted to delete this. It does not answer the question the business asks, which is how long the firm can still be sued over it. The two are related but not identical, and treating them as the same is how an organization destroys something it should have preserved. A second tag, carried in metadata only, separates them.

What it produces. Filtering an asset by limitations tag returns its open legal exposure on a single screen: every document still inside a live limitations window, and which window it sits in. Retention clock

|Stored facts, calculated dates

A stored countdown is wrong the following morning. A stored fact stays true until the world changes. So the proposal records facts against each document and computes every date at the moment someone looks at it.

Stored
Facts recorded against the document
  • Document type, the tag
  • Trigger event, what starts the clock
  • Trigger date, or not occurred
  • Source of that date, document or system
  • Extraction confidence, 0 to 1
  • Hold status and hold reference
  • Rule version applied
Calculated
Computed on read, never written
  • Retention rule that applies
  • Destruction-eligible date
  • Time remaining, to the day
  • Clock state, one of four
  • Limitations window, open or closed
  • Days until that window closes

Why it matters operationally. When the law changes, and four chapters of it change on 1 January 2028, a rule table is re-run rather than forty thousand documents re-read. The facts are already correct; only the arithmetic moves. Why it matters legally. Every date on screen is traceable to this document, this extracted fact, this rule, and this version of the schedule approved on this date. That audit trail is what makes a destruction defensible rather than merely explainable.

Two clocks

|Worked example

The retention clock answers when the firm may destroy a record, and drives storage, the annual purge, and defensibility. The limitations clock answers how long the firm can still be sued over it, and drives disclosure at sale, insurance at renewal, and diligence at acquisition. They diverge. A roof replacement substantially complete on 5 September 2026 produces two documents from the same job with two different answers.

Why the example matters The project file becomes destructible roughly a year after the repose bar runs, deliberately. The certificate never becomes destructible at all, because it is the only document that proves when the repose clock started. Neither answer is visible from the folder the documents sit in. That is the case for calculating rather than remembering.

Pipeline

|Arrival to destruction
  1. Intake. The document is filed and named. Naming happens at filing, never afterwards.
  2. Extraction. AI reads the document and returns document type, trigger event, trigger date, and a confidence score.
  3. Review gate. Anything below the confidence threshold goes to a queue for a person. Nothing passes silently.
  4. Rule engine. A deterministic lookup maps type to retention rule and to what starts the clock. No AI judgment at this step.
  5. Operational join. AppFolio, transaction, and HR records supply trigger dates the document cannot know: lease ended, deal closed, employee separated.
  6. Live compute. State and countdown are rendered on read and recomputed nightly. Never written to storage.
  7. Approval gate. The system proposes the purge list, the Records Owner approves it, and every file is logged. Nothing deletes itself.

Consequence of the operational join. Once it is in place, the monthly open-clock reconciliation stops being a manual task: a tenancy ends in AppFolio and the clock starts on its own. That reconciliation is currently the single point at which the whole system fails if a person forgets. It is also the reason the AppFolio Database API in the next section is a dependency of this work rather than a parallel request.

State
Clock not started

State

Past the destruction date. Enters the next proposed purge list and waits on Records Owner approval.

Litigation hold, which overrides every rule. Does not count down, is never proposed, and is released in writing only.

Reporting

|One screen per division
  • Destruction ready. Count and volume eligible now, by division and by asset, with one click to produce the proposed purge list.
  • Clocks not started. Aged, with the exception report as the valuable half: files still open against a lease that ended, a deal that closed, or an employee who left. None of this is visible today.
  • Open legal exposure. Per asset, every document inside a live limitations window and which window it sits in.
  • Completeness. Which required records are missing: no completion certificate on a finished capital project, no move-in checklist on a tenancy holding a deposit, no current certificate of insurance on an active vendor.
  • Review queue. Low-confidence extractions waiting on a person, sized and aged, so the backlog is visible rather than silent.
  • Hold register. Everything currently frozen, why, and by whom.
  • Audit readiness. Trust records and the contract log, filtered and current, against a Licensing audit that may arrive unannounced and expects the first package inside two business days.

Guardrails

|Non-negotiable
  • Nothing deletes itself. The system proposes, the Records Owner approves, and every destroyed file is logged permanently. This is both a legal requirement and what stops a model error from becoming a spoliation problem.
  • A date may only lengthen. If a recompute would shorten an existing destruction date it flags for review instead of moving it. Shortening requires written approval, logged.
  • Low confidence means a person. Extraction below the threshold never silently assigns a date. It queues.
  • The rule table is versioned. Counsel-approved, dated, and version-stamped on every calculation, so any date on screen can be reconstructed years later against the rules in force when it was set.
  • The schedule is an opinion. The rule table interprets statute. It requires legal sign-off before it counts down against a real document, and a mandatory review before 1 January 2028, when the association chapters are repealed.

Argument against Starter. Advanced at $24.99 per seat per month is 2.3 times the cost and adds portfolios, goals, workload management, approvals, and time tracking. Not addressed by Starter. Starter has no SAML single sign-on and no SCIM provisioning; sign-in is by password or Google authentication rather than through a central identity provider. What we are watching

|Four risks
Adoption
Inconsistent use
A tool used by part of the team produces a partial record. Message history, meeting notes, and shared component libraries return value in proportion to how completely they are populated. A month in which a tool is skipped produces no record for that month, and the gap is not visible until someone needs it. The license is paid either way.
Drift
Upkeep without an owner
Each tool needs continuous small effort that belongs to no single role: channels created and archived, requests and messages answered, a recording started at the beginning of every meeting, design files and components tidied as they accumulate. None of it is difficult. All of it stops when no time is set aside for it, and the tools degrade quietly rather than failing outright.
Onboarding
Habits inherited rather than taught
New staff copy what they see. If the expected use is not demonstrated in the first week, what they adopt is whatever the team is doing at the time, including the parts that have already drifted. Drift compounds through each person added.
Renewal
Seats renewing without a usage check
Licenses renew on their own. Without a usage review before the renewal date, a seat that has gone unused continues to be paid for, and the first signal is the invoice. This is the risk that converts an adoption problem into a cost problem.
